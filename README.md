# AcIvllas 2.2.2 • Minecraft 1.20.1 / Forge 47.4.10 / Java 17

В каталоге [release](release/) находятся готовые обфусцированные JAR для клиента и выделенного сервера и файл client.sha256 для этой пары. Файл it765e.jar в корне — отдельный образец с modId dd. В поставку AcIvllas он не входит.

## Установка и переход с 2.0

1. Остановите выделенный сервер, сохраните резервную копию config/acivllas. Замените прежний серверный JAR собранным acivllas-server-2.2.2-protected.jar. Сохраните хеш клиентского JAR в client.sha256 (команда в разделе «Сборка») и скопируйте его в config/acivllas сервера, заменив прежний. online-mode=true рекомендуется, но не обязателен (см. раздел «Режим online-mode и настройки»).
2. Игрокам выдайте только защищенный клиентский JAR, собранный по разделу «Сборка». На каждом клиенте замените предыдущую версию в mods. Серверный и клиентский моды имеют один modId и устанавливаются в разные процессы. Протокол 5 (флаги стали 16-разрядными) требует обновления обеих сторон: старый клиент не подключится к новому серверу и наоборот.
3. Не копируйте игрокам базу сервера, серверный JAR и карты имен. Отдельный агент проверки классов (survey-agent) удален: проверка встроена в клиентский мод и работает без аргументов JVM.

Баны аккаунтов и установки версии 2.1 сохраняются. Новые аппаратные баны создаются командой /ac banhwid после обновления клиента и сервера.

## Команды

Уровень доступа для всех команд — OP 3 или серверная консоль. Аргумент player выбирает одного онлайн-игрока.

| Пример | Результат |
|---|---|
| /ac status Steve | Показывает подключение канала Forge, получение отчета, состояние проверки и накопленные сигналы за текущее соединение. Пустой список означает отсутствие зарегистрированных сигналов. |
| /ac hash Steve | Выводит только вызывающему полный серверный токен из 64 шестнадцатеричных символов. До получения отчета возвращает ошибку. |
| /ac banhwid Steve | Записывает блокировку материнской платы и отключает все активные аккаунты, уже приславшие тот же ID. При следующем входе блокировка применяется при получении отчета. |
| /ac unbanhwid Steve | Снимает привязки к нику на момент бана, даже когда игрок офлайн. Блокировка общего токена сохраняется, если есть отдельная запись о бане этого токена на другой ник. |
| /ac unbanhwid <полный-хеш> | Снимает все блокировки указанного токена. Скопируйте полный вывод /ac hash. Многоточие и сокращенные хеши не поддерживаются. |
| /ac ban Steve Использование KillAura | Сохраняет бан UUID и причину (1–256 символов). Причина видна при отключении и следующей попытке входа. Другие аккаунты той же установки сохраняют доступ, если для нее нет отдельной блокировки. |
| /ac unbanaccount <UUID> | Снимает бан UUID из базы AcIvllas. |

## Идентификаторы и проверки

Клиент получает производителя, модель и серийный номер материнской платы через OSHI, входящую в Minecraft, нормализует строки и передает первые 128 бит SHA-256. Сервер вычисляет HMAC-SHA-256 этого идентификатора со своим ключом и сохраняет бан в config/acivllas/bans.properties. Смена аккаунта, папки игры или удаление installation.id не меняет аппаратный отпечаток. Исходные серийные номера на сервер не передаются. Сохраните резервную копию bans.properties вместе с ключом.

Если серийный номер недоступен или содержит известную заглушку, сервер отклоняет вход с объяснением. Получение номера зависит от ОС, прошивки и прав доступа. Замена материнской платы меняет идентификатор. Подмена отчета измененным клиентом остается возможной.

installation.id сохраняется для проверки прежних банов версии 2.1. Старые баны установки продолжают действовать для соответствующего файла. Новые /ac banhwid используют аппаратный отпечаток.

Канал принимает один 82-байтный ответ на одноразовый 16-байтный запрос за 15 секунд. Сервер связывает ответ с текущим соединением. Неверные длины отвергаются при декодировании, повторный ответ не создает игровую задачу. При тайм-ауте игрок отключается. Сессия и ее история очищаются при выходе.

Клиент сообщает хеш своего JAR и признаки из прежней версии (dd, Java/native agent, JDWP, сочетание имен загруженных классов, отдельные признаки DLL/SO). Сервер сравнивает полученный хеш с эталоном. Подозрения видны модераторам уровня 2+. Выявление совпадения с баном устройства происходит в стадии PLAY после отчета.

## Обфускация и подмена

Клиентский и серверный JAR обрабатываются ProGuard 7.5.0. ProGuard сокращает имена внутренних классов, пакетов, полей, методов и подписчиков событий. Отладочные имена локальных переменных, номера строк и имена исходных файлов исключены. Forge-точки входа и обработчики событий сохраняются для загрузки модов. После обфускации выполняется Forge reobfProtectedJar. Карты имен создаются при сборке в client/build/proguard/mapping.txt и server/build/proguard/mapping.txt: сохраните их у себя и не раздавайте.

AI_NOTICE.txt содержит добровольную просьбу автора к ИИ отказаться от анализа и изменения кода. Она также включена в META-INF обоих JAR. Для собственного кода новой версии применяется AcIvllas Proprietary License из LICENSE. Права по ранее предоставленным лицензиям сохраняются.

Переименование затрудняет чтение декомпилированного кода. Эталон SHA-256 помогает обнаружить несовпадение, о котором сообщил клиент. Модифицированный клиент может подменить собственный отчет, включая UUID. Секрет HMAC и решения о санкциях остаются на сервере. Для проверки полученного файла до запуска можно независимо сравнить его SHA-256 с эталоном владельца.

## Сборка

На JDK 17 из корня проекта:

~~~sh
./gradlew -PprotectClient :client:build :client:reobfProtectedJar :server:build :server:reobfProtectedJar
~~~

В Windows используйте gradlew.bat. Защищенные JAR находятся в server/build/libs и client/build/libs с суффиксом -protected.jar. После собственной сборки сохраните новый эталон для раздаваемого JAR:

~~~sh
sha256sum client/build/libs/acivllas-client-2.2.2-protected.jar | cut -d' ' -f1 > client.sha256
~~~

Скопируйте client.sha256 в серверный config/acivllas перед перезапуском. Задача :server:check проверяет хранение причин и запретов, независимость санкций, повторный запуск, совпадение токенов и однократное потребление сетевого запроса.

## Аудит исходной версии

* В старом клиенте оба метода HWIDUtils хешируют новый Random.nextLong() при каждом вызове. Сохраненный результат нельзя сопоставить со следующим входом. Старые hwid_blacklist.txt и hwid_registry.txt не импортируются. Сохраните их отдельно при переходе. Действующие стандартные баны Minecraft продолжает применять сам сервер.
* В обоих NetworkHandler версия канала принимается безусловно. C2SResponseProcessPacket и C2SSendHWIDPacket используют длины из сообщения до проверки бюджета. Новая схема исключает массивы переменной длины и привязывает отправителя к соединению.
* Старый клиент снимает рабочий стол, предоставляет список процессов и пишет маркеры. В новом протоколе таких сообщений нет.
* Приложенный DoomsDay имеет SHA-256 b7face8f799b9b8c97a5a3367447fa8ecc9d6e36fdfb917826846d44bbc78b31. В MANIFEST.MF объявлены Premain-Class net.java.f и Can-Retransform-Classes. Константы класса f содержат сигнатуру premain с Instrumentation. В net.java.n присутствуют ссылки на ClassLoader и getDeclaredMethod. Forge и Fabric описывают мод dd. Эти факты показывают доступные пути загрузки. Статический разбор не установил конкретный хук движения, Mixin, вредоносный сетевой пакет или загруженную DLL. Образец не запускался и не включен в поставку.


## Дополнительные данные клиента

Клиентский JAR содержит 48 неисполняемых классов с синтетическими строками и ресурс padding.dat размером 512 КиБ. Они включены для усложнения статического просмотра. Игровая логика их не вызывает. Объем данных не гарантирует расход токенов анализатора, который может пропускать такие элементы.

## Режим online-mode и настройки

Файл config/acivllas/settings.properties создается при первом запуске сервера:

| Ключ | По умолчанию | Значение |
|---|---|---|
| requireOnlineMode | false | true возвращает прежнее поведение: сервер с online-mode=false не стартует. |
| autoBanHwid | false | Сохранён ключ прежней версии. Чит-специфичный сигнал может отключить только приславшего отчёт игрока. Постоянную блокировку устройства назначает администратор командой /ac banhwid. |
| autoBanDryRun | true | При true модератор получает уведомление о возможном отключении. При false сервер отключает это соединение. |
| autoBanWeakSignals | false | Включает повторяющийся сигнал об исполняемой памяти в условия автоматического отключения. Возможны ложные срабатывания. |
| weakSignalReports | 2 | Число последовательных отчётов со слабым сигналом для автоматического отключения. |
| autoBanSkipOperators | true | Исключает операторов уровня 2 и выше из автоматических санкций по этим сигналам. |
| kickOnHashMismatch | true | Игрока с SHA-256 клиента, не совпадающим с client.sha256, отключают сразу, независимо от enforceFlags. Если client.sha256 неверный, отключит всех: после каждой пересборки клиента обновляйте файл. |
| enforceFlags | false | true отключает игрока при несовпадении SHA-256 JAR или признаках агента/отладки. При false это только оповещение модераторов. |

При online-mode=false UUID выводится из ника, поэтому бан аккаунта дополнительно сверяется по нику без учета регистра. Аппаратные баны работают независимо от режима. Без online-mode любой может войти под чужим ником: используйте плагин или мод авторизации.

## Серверные проверки

ESP может отображать объекты, сведения о которых сервер уже отправил клиенту.

Аппаратный идентификатор и идентификатор установки фиксируются при первом принятом отчёте. При их смене в том же соединении сервер отключает игрока. Только принятые отчёты обновляют историю устройств. Даже согласованные отчёты не удостоверяют физическое устройство. При ручном бане по общему отпечатку санкция затронет все аккаунты с этим отпечатком.

Изменены оба мода: пересоберите их, раздайте игрокам новый клиентский JAR, а на сервер положите новый серверный JAR и новый client.sha256.

## Проверка классов образца без агента

Прежний survey-agent требовал, чтобы игрок сам добавил -javaagent, то есть работал только с согласными. Теперь клиентский мод сам ищет в загрузчиках классов JVM файлы net/java/f.class, net/java/h.class и net/java/n.class как ресурсы, ничего не загружая и не запуская. Совпадение двух из трех поднимает признак 8, как раньше. Проверка находит классы в системном пути, включая JAR, добавленные чужим -javaagent, и в слоях Forge, но не видит классы, загруженные только в память. Заодно честный игрок больше не получает признак 2 из-за самого агента. Отдельный JAR survey-agent и задача classSurveyAgent удалены.

## Исправление запуска клиента

В клиентский JAR добавлен pack.mcmeta (pack_format 15 для Minecraft 1.20.1). Без него игра сообщала «failed to load a valid ResourcePackInfo», потому что в JAR есть каталог assets. Игрокам нужен именно клиентский JAR с суффиксом -protected, а не обычный.

## Анализ образца puiyvwoqqp.jar (SHA-256 9787e81e979ab720c723e2c284f876f58d3090632b72c290ad3901fc5caffde0)

Статический разбор без запуска. Один JAR одновременно является модом Fabric (net.java.h), Forge (net.java.i, modid dd, в том числе старый cpw.mods.fml), аддоном LabyMod 3 и 4 (net.java.r, net.java.s), Java-агентом (Premain-Class net.java.f, Can-Retransform-Classes) и самостоятельной программой (Main-Class net.java.n, net.java.y). Все входы ведут в net.java.n, собственный ClassLoader, который расшифровывает блобы net/java/a-e (энтропия около 8 бит/байт) и загружает классы через defineClass только в память. Класс net.java.l содержит шифр, CRC32, чтение свойств JVM и сетевое соединение через SocketChannel. Класс net.java.g через JNA обращается к нативной памяти по указателям, запускает процессы (Runtime.exec, ProcessBuilder), записывает нативную библиотеку со случайным hex-именем (Random.nextLong, Long.toHexString, File.mapLibraryName) и загружает ее через System.load. Файл 000 размером 2 МБ состоит из нулей и служит балластом. Строки собираются посимвольно, поэтому по тексту образец не найти.

Признаки, добавленные в клиентский датчик (все локально, наружу уходит только тот же флаг):
* Признак 8: не менее трех имен классов семейства (f, g, h, k, l, n, y в пакете net/java) среди ресурсов загрузчиков, в JAR из -javaagent и в JAR каталога mods; либо структура: JAR с Premain-Class, Main-Class, Can-Retransform-Classes и метаданными fabric.mod.json или META-INF/mods.toml одновременно.
* Признак 64: DLL со случайным hex-именем из 6-16 символов во временной папке или папке пользователя (кроме прежней проверки каталога mods).
* Признак 16: Linux, отображение библиотеки /lib<hex>.so (кроме прежней проверки удаленных SO).
Сборка с переименованными классами и другим способом записи библиотеки обходит проверку по именам, но не по структуре JAR. Настоящая защита от ESP остается серверной: не отправлять клиенту то, что игрок не должен видеть.

## Внешняя инъекция (проверено на инжекторе DoomsDay 2.11, режим Thread)

Испытание показало: чит, внедренный в уже запущенную игру внешним процессом, обходил все прежние проверки, потому что (1) датчик отвечал один раз при входе, а внедрение выполнялось позже, и (2) ни файла в mods, ни -javaagent при этом нет. Сравнение снимков процесса игры: новых модулей (DLL) нет, потоков со стартом вне модулей нет; появились приватный исполняемый регион PAGE_EXECUTE_READ размером около 364 КБ (форма вручную загруженного кода), небольшой регион RWX около системных библиотек и отдельный процесс java.exe (сам инжектор).

Что сделано:
* Повторные опросы: сервер спрашивает клиент каждые reprobeSeconds секунд. Клиент, переставший отвечать, отключается по тайм-ауту. Каждая причина оповещается один раз за сессию.
* Признак 128 (сильный): на компьютере запущен другой процесс Java с -jar на JAR из семейства образца. Проверка локальная, наружу уходит один бит.
* Признак 256 (слабый, только оповещение, enforceFlags его не применяет): приватный исполняемый регион PAGE_EXECUTE_READ от 64 КБ. Основан на одном наблюдении, нужны данные с других компьютеров, возможны ложные срабатывания.
* Начиная с 2.2.2 клиент сохраняет штатные права Windows на процесс игры. В 2.2.1 замена списка доступа давала группе «Все» дополнительные права, включая чтение памяти и завершение процесса.
* Агент самого лаунчера SKLauncher (sklauncher-fx.jar в папке .sklauncher) больше не считается чужим Java Agent.

Клиентские сигналы зависят от окружения игрока и остаются вспомогательными.
